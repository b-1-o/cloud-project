# ADR 0001: Yjs CRDT instead of OT

Status: Accepted for the MVP.

Context: concurrent editors send operations out of order, disconnect, and later reconnect with offline edits. Operational transformation needs a central transform pipeline and ordering rules for each operation type.

Decision: use Yjs shared document updates. Updates merge deterministically and suit offline-first editing. The browser stores state in IndexedDB; the per-document Durable Object serializes persistence and broadcasts accepted updates.

Trade-offs: CRDT metadata and update history consume storage, clients must keep compatible schema/fragment names, and compaction is required. The current room snapshots every 100 persisted updates. Production should bound document size and keep a recovery retention policy. The transport protocol is intentionally small; add protocol version negotiation before mixed client versions are supported.
